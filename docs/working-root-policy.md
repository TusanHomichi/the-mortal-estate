# Working-root policy

## What this document is

This tree has an **ignored working root**: local files that exist so that
iteration is fast, and that no build, test, proof, or release may depend on. It
is the successor's redesigned form of the predecessor's ignored preview lane,
which owner ruling D6 kept rather than retired —

> because fast visual iteration and the Workbench require it. It is redesigned,
> not ported, and it carries six requirements.

This document owns those six requirements for the **whole** ignored root.
[Workbench V0](workbench-v0.md#d6-compliance) states how the Workbench's session
directory meets them; that table stays, and this one is the wider rule it lives
inside. Where they touch the same fact, this document is the owner and the
Workbench spec points here.

## Why this and not public-boundary-policy

[The public boundary policy](public-boundary-policy.md) answers *may this
material exist in this project at all* — provenance, payload, the clean break.
This answers a different question: *what may a local, disposable, untracked file
be allowed to influence.* A candidate frame with impeccable provenance still may
not become runtime input, and a session log with none is fine as long as nothing
reads it. The two rules are orthogonal, and folding this into that document
would put two different questions under one heading — the drift the boundary map
exists to prevent.

## The roots

Everything `.gitignore` declares, and what each is for:

| Root | What lives there | Who writes it |
| --- | --- | --- |
| `.workbench/` | Workbench sessions: selection packets, masks, captures, the operation log, and — since V1 — **experiments and candidates**: previews, applied candidate masters, candidate projections, edited candidate assets, Apply receipts and rejection records | `tools/workbench/`, `tools/workbench_demo.py` |
| `.boundary/` | The private banned-term denylist. Never committed, in any form | the owner, out of band |
| `target/` | Cargo build output for **this** tree. A *proof* build is not this root — see below | cargo |
| `web/node_modules/`, `web/dist/` | The browser client's installed dependencies and its build output. Restored from the committed lockfile by `npm ci`; never runtime input, never tracked | npm, `vite build` |
| `Research/`, `placeholders/` | **Nothing.** Predecessor-private roots, ignored so a stray copy cannot be committed, and asserted absent from disk | nobody — `clean-room` proves they do not exist |

## The six requirements

Owner ruling D6, requirement by requirement, with what holds each one *in this
tree* rather than a promise to hold it.

| D6 requirement | How this tree meets it | Proof |
| --- | --- | --- |
| Tracked builds, tests, release content, and public-boundary proof **never depend on the ignored root** | No step in the verification runner's complete lane names any ignored root, in either its ordinary or its degraded form. The one tool that writes a session — `tools/workbench_demo.py` — seeds it from the **tracked** capture fixture, so it runs on a clean clone with `.workbench/` absent | `tests/test_working_root.py::TrackedProofNeverDependsOnTheIgnoredRoot` — asserted against the resolved step table, which is what a run executes, not against a reading of the tools |
| Clean clones carry **tracked synthetic fixtures** for automated proof | `tests/fixtures/synthetic-terms.txt` (the banned-terms mechanism), `tools/ci-synthetic-banned-terms.txt` (the same, for CI), `tests/fixtures/workbench/` (a complete synthetic land, session, packets, masks and log, regenerated by `regenerate.py` and byte-checked), `tests/fixtures/capture/` (two real captures of one real frame, with `provenance.md`) | `tests/test_working_root.py::CleanClonesCarryTrackedFixtures` names each one and asserts git carries it. `tools/run_clean_clone_proof.py` then builds and tests a copy of the carried set with every ignored root absent |
| Missing private fixtures produce an **honest unavailable result, never a false pass** | The runner probes capabilities once and reports `UNAVAILABLE` with the reason; an unavailable step does not run and the whole verdict becomes `INCOMPLETE` (exit 3). The banned-terms check *degrades* rather than skipping — it runs its real matching and fail-closed machinery against the tracked synthetic list — and the degradation is printed as a degradation. Every boundary check still exits **3 FAIL CLOSED** on a missing input, which is neither a skip nor a pass | `tests/test_verification_execute.py::UnavailableIsNeverPass` and `::Degradation`. The exit-code contract is in `tools/run_verification.py --help` |
| Candidate and session files **carry source hashes and cannot become runtime input** | Every Workbench packet and session manifest binds the digests of the files it was derived from, and the manifest states `runtime_input: false`. The rule this document adds is the enforcement: **no carried file outside `tools/workbench/`, its scripted proof, the tests, and the documents that state the policy may name the session root at all** — and specifically nothing in `crates/` or `client/` may | `tests/test_working_root.py::NoTrackedLoaderReadsTheIgnoredRoot` — a fail-closed check over the carried set, so a loader added later that reads a session turns the suite red. Per-digest staleness is `tests/test_workbench_staleness.py` and `tests/test_capture_addressing.py::ACapturePacketFailsClosedPerDigest` |
| Retention and cleanup are **explicit** | The ruling below, and `python3 tools/workbench_prune.py` implements it | `tests/test_workbench_session.py`; the policy text is restated in every session manifest |
| Accepted outputs enter tracked content **only through the promotion path** | The Workbench cannot write tracked content at all. Anything that becomes content goes through `crates/tme-authoring`'s promotion gate, which refuses an artifact without its authoring receipt | `crates/tme-authoring/tests/promotion_gate.rs`; the contract is [authoring-contracts.md](authoring-contracts.md) |

## Candidates and experiments

Workbench V1 puts two more classes of file under this root, and both are covered
by the rules above rather than excepted from them.

- **Experiments** — a staged operation and the preview it produces. Disposable
  by definition, overwritten by the next preview, and never named by anything.
- **Candidates** — what an Apply wrote: a candidate master, its projection, any
  edited assets, and a receipt naming every base digest and every output digest.
  Still ignored, still not tracked, still not an authority.

Three properties make them safe to have here, and each is enforced rather than
intended:

1. **They cannot be written anywhere else.** Every V1 artifact path is made by
   `Session.artifact`, which refuses a path that escapes the session directory.
   A caller that tries to write tracked content through it is refused, and that
   refusal has its own mutant.
2. **They carry their source hashes.** A receipt names the base digests it was
   produced from, the operation set, and the digest of every output.
3. **They cannot become tracked content except through the promotion path.**
   Apply grants nothing: its receipt records `promotion: false`,
   `tracked_write: false`, `runtime_input: false`. An accepted candidate becomes
   an accepted master only by the owner ceremony that re-signs that land's
   `promotion.json` and changes its reviewed `master_digest`, together, in one
   commit —
   which is measured in
   [Workbench V1](workbench-v1.md#5-the-second-promotion-anchor-spec-134).

The state-3 exemplar this slice added — `content/authoring-fixture/fixture-swatch.png`
and its provenance record — is **tracked**, deliberately, and is therefore
outside this root entirely. It is the thing a candidate is an edit OF.

## The retention ruling

Workbench spec §13 left retention as an open decision. It is ruled here, at plan
level, because "disposable" without a number is a directory that grows until
somebody notices.

**Sessions are disposable working state with no retention guarantee at all.**

- **Keep** the session you are working in. Nothing else.
- **`rm -rf .workbench/` is always a safe command in this repository.** No
  tracked file references a session, so no deletion can break a build, a test,
  a proof, or a promotion. This is a property the tests above hold, not a
  convention.
- **Automatic cleanup: sessions older than 14 days, and any session beyond the
  most recent 10, are removed by `tools/workbench_prune.py`.** Fourteen
  days is chosen to be longer than any plausible single piece of work and shorter
  than the interval at which anyone would think to look. The prune never touches
  the session named by an active `--session`.
- **A session left open commits to nothing.** Reopening one after a prune costs
  the gestures again; it cannot cost correctness, because the packets it held
  were bound to digests and would have failed closed anyway.
- **`target/` and `.boundary/` are outside this schedule.** Cargo owns the first;
  the owner owns the second and it is never deleted by a tool in this tree.
- **A proof owns the build output it creates, and deletes it.** `target/` is the
  developer's working build, kept because the next build is faster for it. The
  build a *proof* makes has no next build: `tools/run_clean_clone_proof.py`
  builds into a scratch directory beside its copy — never inside it, so the copy
  stays exactly the carried set for the whole run — prints that directory's peak
  size, and removes it in `finally` on success, on failure, and under `--keep`.
  How large it is allowed to be, and the arithmetic that decides it, belong to
  [agent workflow](agent-workflow.md#the-disk-budget).

Captures live inside a session and share its retention. The two captures under
`tests/fixtures/capture/` are the deliberate exception: they are tracked proof
material with their own provenance record, and they are not working state.

## What this forbids, plainly

- A test, build, content load, or boundary check that reads anything under an
  ignored root.
- A tracked default, fallback, or configuration value that points into one.
- A "just this once" copy out of a session into `content/` without the
  promotion path.
- Treating an absent private fixture as a pass. The word for that here is
  `UNAVAILABLE`, and it makes the run `INCOMPLETE`.
